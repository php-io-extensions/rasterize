# Agent guidance — php-io-extensions/rasterize

1. **Read [`.okf/index.md`](.okf/index.md) first** before changing the API, the C, or packaging. Open only the concepts the change touches.
2. **Geometry only.** `RasterScanner` answers span bytes and `RasterStroker` answers contours and dash pieces; neither touches a pixel. No pixel stores, no colours, no dependency, no framework names. See [`.okf/api/scanner.md`](.okf/api/scanner.md) and [`.okf/api/stroker.md`](.okf/api/stroker.md).
3. **Plain C on the Zend API.** No Zephir, no FFI, no system library. `src/core.{h,c}` (the scanner) and `src/stroke.{h,c}` (the stroker) are plain C with no Zend in them and take their memory through the two function pointers the class passes; `src/RasterScanner.c` and `src/RasterStroker.c` are the classes over them; `src/rasterize.c` is the module and its constants.
4. **The stubs are the declaration.** Edit `stubs/*.stub.php`, regenerate the matching `*_arginfo.h` with gen_stub, commit both. Never hand-edit arginfo. See [`.okf/runbooks/build.md`](.okf/runbooks/build.md).
5. **The span bytes are a contract.** 7 bytes, little-endian `y`, `x`, `length` (uint16) and `coverage` (uint8); rows ascending, `x` ascending, no overlap, coverage 1..255, an empty string for nothing. Consumers parse them as they are.
6. **The arithmetic is a contract.** The scanner is IEEE double with `+ − × ÷`, `sqrt`, `floor` and `ceil` in the order [`.okf/api/scanner.md`](.okf/api/scanner.md) writes down, so the same input answers the same bytes on every platform and from a PHP implementation of the same steps. The stroker is the same, in the order [`.okf/api/stroker.md`](.okf/api/stroker.md) writes down, and also calls the C library's `hypot`, `fmod`, `atan2`, `acos`, `sin` and `cos`, as PHP does: it answers the same bits as PHP on one machine, and another platform's library may differ in the last bit. A change to either changes every caller's output: it needs its reason, and its tests work the expected numbers by hand.
7. **Three flags stay in `config.m4`.** `-ffp-contract=off`: without it the compiler fuses multiply-adds in `core.c` and `stroke.c` and the numbers move. `-fno-builtin-sin -fno-builtin-cos`: without them it joins the sine and cosine of one angle into a single `sincos` call whose last bit differs from separate `sin()` and `cos()`. Check with `objdump -d src/.libs/core.o src/.libs/stroke.o | grep -c fmadd`: 0, and `nm -u src/.libs/stroke.o | grep -i sincos`: nothing.
8. **Refuse, don't guess.** A non-finite coordinate, one past `RASTER_LIMIT`, a malformed list, an unknown rule, cap or join is a `ValueError` naming what was wrong, before any scanning or stroking. A division by a length or a width that is 0 is a `DivisionByZeroError`, as it is in PHP.
9. **NTS and ZTS.** No module globals. Every change builds with `-Wall -Wextra` without a warning from `src/` and passes Pest under NTS and ZTS on macOS and Linux.
10. **Tests are Pest v4 and hardware-free.** Expected spans come from the edge rules, worked by hand.
11. **Durable facts go in `.okf`.** Update the matching concept, bump its `generated.at`, append `.okf/log.md`. The bundle documents the package, never a session.
12. **Version**: `PHP_RASTERIZE_VERSION` moves only past a published tag; tags drive Packagist.
